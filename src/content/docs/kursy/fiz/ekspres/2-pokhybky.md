**3 год.** Жоден вимір не дає «справжнього» числа. Він дає інтервал, у якому справжнє значення лежить з великою ймовірністю. Записати результат вимірювання — означає записати цей інтервал: **x = x̄ ± Δx**.

## Прямі й непрямі виміри

- **Прямий** — число дає прилад: мультиметр показує напругу, Arduino — код АЦП.
- **Непрямий** — число обчислюємо з прямих: струм I = U / R з виміряної напруги і відомого опору.

Похибка непрямого виміру складається з похибок усіх прямих, з яких його пораховано.

## Звідки береться похибка

**Випадкова похибка.** Повтори вимір 20 разів — числа трохи різнитимуться: шум, наводки, тремтіння руки. Випадкова похибка змінюється від виміру до виміру і в середньому компенсується. Її зменшують повторенням.

**Систематична похибка.** Зсуває всі виміри в один бік однаково: прилад неправильно відкалібровано, Arduino вважає, що живлення 5,00 В, а воно 4,82 В. Усереднення її не зменшує — 1000 вимірів дадуть дуже точне, але зсунуте число. Її шукають, порівнюючи з іншим приладом або методом.

**Похибка приладу.**

- Шкала зі стрілкою — половина ціни поділки.
- Цифровий прилад — за паспортом, зазвичай у вигляді ±(a % від показу + b одиниць останнього розряду). Наприклад, ±(0,5 % + 2): при показі 1,523 В на межі 2 В це 0,005 × 1,523 + 2 × 0,001 ≈ 0,010 В. Знайди паспорт свого мультиметра — точні числа в кожної моделі свої.
- АЦП — щонайменше половина кроку квантування (докладно в [занятті 4](/kursy/fiz/ekspres/4-arduino/)).

## Середнє і розкид

Для серії з n вимірів x₁ … xₙ:

- **середнє** x̄ = (x₁ + … + xₙ) / n;
- **стандартне відхилення** s = √( Σ(xᵢ − x̄)² / (n − 1) ) показує, наскільки розкидані окремі виміри;
- **похибка середнього** Δx̄ = s / √n показує, наскільки точно ми знаємо саме середнє.

Тому середнє з 20 вимірів у √20 ≈ 4,5 раза точніше за один вимір — але лише щодо випадкової похибки.

У LibreOffice Calc: `=AVERAGE(B2:B21)`, `=STDEV(B2:B21)`, `=STDEV(B2:B21)/SQRT(COUNT(B2:B21))`. Якщо Calc показує назви функцій українською, увімкни англійські: Tools → Options → LibreOffice Calc → Formula → Use English function names.

## Повна похибка

У цьому модулі складаємо похибки **простим додаванням** — це оцінка зверху, з запасом:

Δx = Δx̄ (випадкова) + Δприл (прилад)

Точніший спосіб — корінь із суми квадратів: Δx = √(Δx̄² + Δприл²). Він дає менше число, бо малоймовірно, що обидві похибки водночас максимальні. Можеш використати його в поглибленому рівні лабораторної — тільки напиши, який спосіб обрав.

## Похибка непрямого виміру

Для **добутку чи частки** (I = U / R, P = U · I) додаються **відносні** похибки ε = Δx / x:

ε_I = ε_U + ε_R, ΔI = ε_I · I.

**Приклад.** U = 1,48 ± 0,02 В, R = 220 Ом ± 5 %.

- ε_U = 0,02 / 1,48 ≈ 1,4 %; ε_R = 5 %; ε_I ≈ 6,4 %.
- I = 1,48 / 220 = 6,73 мА; ΔI = 0,064 × 6,73 ≈ 0,43 мА.
- **I = 6,7 ± 0,4 мА.**

Бачиш, що допуск резистора дає майже всю похибку? Отже, виміряти опір конкретного резистора мультиметром корисніше, ніж робити 200 вимірів напруги замість 20.

## Як записати результат

1. Похибку округлюй до **однієї значущої цифри** (до двох, якщо перша — 1): 0,0433 → 0,04; 0,0137 → 0,014.
2. Значення округлюй **до того самого розряду**, що й похибку: 6,7349 ± 0,4 → 6,7 ± 0,4.
3. Обов'язково з одиницями: **I = 6,7 ± 0,4 мА**.

Записи «I = 6,7349 ± 0,4 мА» і «I = 7 ± 0,43 мА» неправильні: зайві цифри нічого не означають.

## Порівняння прогнозу з виміром

Прогноз і вимір **узгоджуються**, якщо їхні інтервали перекриваються. Не перекриваються — є причина, яку треба знайти: не те значення з даташита, систематична похибка приладу, помилка у схемі. Пошук цієї причини — найцікавіша частина звіту.

## Задачі

1. Мультиметр 8 разів показав напругу: 1,52; 1,49; 1,55; 1,50; 1,53; 1,48; 1,51; 1,54 В. Знайди x̄, s, похибку середнього і запиши результат. Похибкою приладу поки знехтуй.
2. До результату задачі 1 додай похибку приладу ±(0,5 % + 2 одиниці останнього розряду; останній розряд тут — 0,01 В). Яка похибка тепер дає більший внесок?
3. Резистор 470 Ом ± 5 %, напруга на ньому 3,05 ± 0,03 В. Знайди струм із похибкою. Що треба зробити, щоб зменшити похибку вдвічі?
4. Чому серія з 1000 вимірів напруги Arduino, що живиться від USB, не зробить результат точним, хоч похибка середнього стане дуже малою?
