**1 год.** SSH (Secure Shell) — це термінал іншого комп'ютера у твоєму вікні, через зашифроване з'єднання. Так ти працюватимеш з Jetson і LuckFox, на яких немає ні монітора, ні клавіатури, і з сервером академії.

## Ключі замість пароля

SSH може пускати за паролем, але ми користуємося **парою ключів**:

- **приватний ключ** (`~/.ssh/id_ed25519`) лежить лише на твоєму комп'ютері і **нікому не передається**;
- **публічний ключ** (`~/.ssh/id_ed25519.pub`) кладеш на кожну машину, куди хочеш входити.

Сервер перевіряє, що в тебе є приватний ключ до публічного, але сам приватний ключ мережею не йде. Пароль можна підглянути, підібрати чи вкрасти з іншого сайту; ключ — ні. А ще не треба вводити пароль сто разів на день.

```bash
ssh-keygen -t ed25519 -C "ivan-p-ra97"
```

- Місце для ключа — погоджуйся з запропонованим (Enter).
- **Passphrase** — пароль, яким зашифровано сам приватний ключ. Постав його: якщо хтось скопіює файл ключа, без passphrase він ним не скористається.
- `-C` — коментар, за яким ключ упізнають на сервері. Пиши ім'я латиницею, без прізвища повністю.

```bash
ls -l ~/.ssh                  # id_ed25519 (приватний) і id_ed25519.pub (публічний)
cat ~/.ssh/id_ed25519.pub     # публічний — один рядок, його можна показувати
```

Права на `~/.ssh/id_ed25519` мають бути `-rw-------`: читати його може лише власник. Інакше ssh відмовиться ним користуватися.

## Вхід на машину

Адресу навчальної машини, логін і пароль для першого входу дає викладач.

```bash
ssh-copy-id учень@адреса      # покласти свій публічний ключ на машину (пароль — востаннє)
ssh учень@адреса              # увійти: тепер пароль не потрібен (лише passphrase ключа)
hostname; whoami; exit        # де я і хто я там; вийти
```

Під час першого входу ssh покаже **відбиток** (fingerprint) машини і спитає, чи довіряєш їй. Викладач показує правильний відбиток — порівняй. Якщо колись під час входу ssh напише, що відбиток **змінився**, не погоджуйся і скажи викладачеві: так виглядає підміна машини.

:::note[Навчальної машини поки немає?]
Тренуйся на власному Linux у WSL: він теж уміє бути SSH-сервером.

```bash
sudo service ssh start
ssh-copy-id ra97@localhost
ssh ra97@localhost
```

Ти «зайшов» у той самий комп'ютер, але через SSH — з ключем, відбитком і всім іншим, як на справжній машині.
:::

## Копіювання файлів: scp

```bash
scp звіт.md учень@адреса:~/              # свій файл — у домашню теку на машині
scp учень@адреса:~/dani.csv .            # файл з машини — у поточну теку
scp -r laby учень@адреса:~/              # цілу теку
```

Двокрапка відділяє машину від шляху на ній. Без двокрапки scp вважає, що це локальний файл.

## Файл ~/.ssh/config

Щоб не пам'ятати адреси й логіни, дай машині коротке ім'я:

```text
Host ra97
    HostName адреса
    User учень
```

Тепер достатньо `ssh ra97` і `scp звіт.md ra97:~/`.

## Git Bash

У Git Bash усе те саме: `ssh-keygen`, `ssh`, `scp`, `~/.ssh/config`. Лише `ssh-copy-id` може не бути — тоді виконай:

```bash
cat ~/.ssh/id_ed25519.pub | ssh учень@адреса "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"
```
