## Бейдж і захист

Бейдж = обов'язковий рівень міні-проєкту + усний захист 10–15 хв. Будь-який із двох викладачів приймає його за однією рубрикою 0–4 (з донора Edge). Бейдж зараховано, коли всі обов'язкові тести проходять і кожен критерій ≥ 2.

| Критерій | Що перевіряємо | Де |
| --- | --- | --- |
| Працює | автотести проходять на комп'ютері викладача | усі |
| Розуміння | три запитання з паспорта або їх варіанти | усі |
| Зміна наживо | учень змінює свій код на прохання викладача, без ШІ | усі |
| Якість коду | імена, функції з однією відповідальністю; ruff без зауважень (Python), жодного попередження компілятора (C++) | усі |
| Документація | docstring (ПРГ1), README з прикладом запуску (з ПРГ2) | усі |
| Історія Git | осмислені коміти протягом роботи, а не один наприкінці | ПРГ4 (у ПРГ3 — бажано) |

- **Частина коду — на занятті.** Ядро міні-проєкту (для ровера — функція кроку) учень пише при викладачеві, решту — вдома.
- **ШІ-помічники.** У ПРГ1–ПРГ2 ШІ-асистенти на заняттях вимкнені: синтаксис має пройти через руки. Від ПРГ3 дозволено, якщо учень пояснює кожен рядок. Код, який учень не може пояснити або змінити, не зараховується.
- **Автотести — це вчитель, який завжди поруч.** ПРГ1 — готові тести; ПРГ2 — плюс ≥5 власних; ПРГ3 — тести stdin/stdout; ПРГ4 — ≥8 власних doctest. Тести запускаються локально, без інтернету; Завдання й тести лежать у шаблонних репозиторіях академії, GitHub Classroom не використовуємо.
- **Доказ для реєстру бейджів** — посилання на репозиторій учня або на архів роботи. Учень бере шаблон завдання архівом або створює з нього власний репозиторій. До ПРГ4 власний репозиторій — за бажанням, а доказ — архів у спільній теці академії; у ПРГ4 він потрібен, бо оцінюється історія Git.
- **Не склав** — повторний захист через тиждень із іншою зміною наживо. Екстерн дає лише одну спробу.

## Місце в шляху: варіанти А і Б

У варіанті А курс розтягнутий на два роки з літньою перервою, у варіанті Б стиснутий у пів року: ПРГ1 екстерном, ПРГ2–ПРГ4 — у слоті Ф року 1*. Дати пілоту орієнтовні: п'ять блоків із листопада по травень — це ≈5 робочих тижнів на блок, а не 6.

| Модуль | Варіант А (набір 2027) | Варіант Б (пілот 2026) |
| --- | --- | --- |
| ПРГ1 | рік 0, блок 2 — жовтень–листопад 2027 | екстерн на діагностиці, початок листопада 2026 |
| ПРГ2 | рік 0, блок 4 — лютий–березень 2028 | рік 1*, блок 2 — ≈14.12.2026–31.01.2027, з зимовими канікулами |
| ПРГ3 | рік 1, блок 1 — вересень–жовтень 2028 | рік 1*, блок 3 — ≈01.02–07.03.2027 |
| ПРГ4 | рік 1, блок 2 — жовтень–листопад 2028 | рік 1*, блок 5 — ≈19.04–29.05.2027 |

### Варіант А: що враховано

- Між ПРГ2 і ПРГ3 — пів року перерви. Тому ПРГ3 починається з перенесення ровера з ПРГ1 на C++: це водночас повторення Python і перше зіткнення з типами.
- ФІЗ2 йде в блоці 3, одразу після ПРГ1, тож скетчі Arduino в його лабораторних готові, а дані зберігаються в CSV. ПРГ2 у блоці 4 обробляє саме ці дані: датасет для labkit готовий вчасно.
- ІНС2 (Git) закривається в тому ж блоці 4, тому критерій «історія Git» стартує з ПРГ3–ПРГ4.
- ПРГ4 закривається до першого ЕМБ1.x у будь-якій ролі (найраніше — Програміст ВС, блок 3 року 1).

### Варіант Б: екстерн ПРГ1 і що, якщо не склав

1. Діагностична домашня задача = обов'язковий рівень «Ровера на сітці» із готовими тестами, тиждень вдома. Захист — за тією ж рубрикою, 10 хв замість 5 хв із Карти: три запитання і зміна наживо в 5 хв не вміщаються.
2. Склав — ПРГ2 з блоку 2, як у розкладці.
3. Не склав — ПРГ1 відразу в слоті Ф блоку 1 замість ІНС-експрес. ІНС-експрес переходить у слот Т блоку 4, шлях ролі зсувається на один блок, і в році 2 випадає один вступ. Ланцюжок ПРГ2–ПРГ4 лишається в графіку. Це уточнює фразу Карти «модуль ПРГ1 замість одного вступу»: буквально так не вийде, бо ПРГ2 у блоці 2 вимагає ПРГ1 до грудня.
4. Пропоную також екстерн ПРГ2 за бажанням, спроба до 13.12.2026. Правило це дозволяє (це бейдж року 0), а в варіанті Б немає резерву. Хто склав, звільняє блок 2 слоту Ф і може перенести туди МАТ1.3 з літа 2027.

У пілоті датасет для labkit беремо з ФІЗ-експрес (блок 1), а готовий запасний CSV лежить у матеріалах на випадок, якщо лабораторна зірвалася. Програміст ВС пілоту починає ЕМБ1.1 у блоці 5 одночасно з ПРГ4, тож консоль команд потрапить на ESP32 лише в ЕМБ1.3, у році 2.

## Фізика в курсі

Розділів-власників немає: курс дає фізичним модулям інструмент, а не зміст. labkit (ПРГ2) обробляє дані лабораторних ФІЗ і ЕЛ — середнє, розкид, графік із похибками, — але що таке похибка і як її подавати, вчить ФІЗ1.

Єдина «фізика» всередині курсу — обмеження числа в машині: переповнення і точність float у ПРГ3. Правило «спочатку порахуй» тут звучить як «спочатку порахуй на папері, потім напиши тест»: до запуску учень передбачає, з якого показу сума в uint16_t переповниться.

## Обладнання і ПЗ

Заліза курс не потребує: це єдиний курс Фундаменту, який можна цілком пройти вдома. Усе ПЗ безкоштовне і працює без інтернету після встановлення.

| Модуль | Мінімальний набір | Запасний варіант | ПЗ (безкоштовне, офлайн) |
| --- | --- | --- | --- |
| ПРГ1 | шкільний ноутбук | немає прав на встановлення — Thonny portable з флешки; немає ПК вдома — ноутбук у ліцеї в години самостійної роботи | Python 3.13+, VS Code + розширення Python, pytest |
| ПРГ2 | той самий | інтернет вимкнули під час тривоги — офлайн-кеш на флешці: інсталятори Python і VS Code, розширення (VSIX), пакети у кеші uv; зірвалася лабораторна ФІЗ — готовий CSV у матеріалах | + uv, numpy, matplotlib, ruff |
| ПРГ3 | той самий | домашній ПК без WSL — MSYS2 (UCRT64): g++, gdb і CMake є, ASan немає, замість нього `-D_GLIBCXX_DEBUG` і налагоджувач | Windows 11 + WSL2 з Ubuntu 24.04: GCC 13+ або Clang, gdb, CMake; VS Code + розширення C/C++ |
| ПРГ4 | той самий | як у ПРГ3 | + doctest (один заголовковий файл), CTest, clang-format |

- **Одне середовище на всі роки.** VS Code від ПРГ1 до PlatformIO в ЕМБ1.1: учень не міняє редактор між курсами. Thonny — лише запасний варіант.
- **WSL2 — основне середовище C++ на шкільних ноутбуках (Windows 11).** Це той самий Linux, що в ІНС1, і тільки там повноцінно працюють санітайзери. Встановлюємо його заздалегідь, до ІНС-експрес; відкатний план — налаштований образ Ubuntu для wsl --import у тому ж офлайн-кеші.
- **Код для мікроконтролера — без винятків і в межах C++17.** ESP-IDF 5.5 за замовчуванням збирає C++ як gnu++23, а винятки C++ там за замовчуванням вимкнені ([джерело](https://docs.espressif.com/projects/esp-idf/en/v5.5.5/api-guides/cplusplus.html)). Але PlatformIO зі старим ядром Arduino-ESP32 2.x працює на GCC 8, де C++20 ще немає. Тому вчимося на C++20, а консоль команд у ПРГ4 пишемо без винятків і збираємо тести ще й з -std=c++17: тоді вона переживе будь-який тулчейн, який обере ЕМБ.
- **Версія Python.** Беремо 3.13 або 3.14. Найновішу 3.15 — лише після перевірки, що numpy і matplotlib ставляться без компіляції на шкільних ноутбуках.
- **uv** ставиться в домашню теку користувача ([джерело](https://docs.astral.sh/uv/getting-started/installation/)), тож зазвичай не потребує прав адміністратора. Запасний шлях — стандартні `python -m venv` і pip.

## Підсумковий артефакт курсу

Після курсу в репозиторії учня залишаються два інструменти, якими він користується в треках: labkit і консоль команд. Курс Фундаменту не залишає плати чи вузла, тож артефакт тут — код, який працює в чужих курсах (принцип 5).

| Артефакт | Модуль | Де працює далі |
| --- | --- | --- |
| Консоль команд — бібліотека C++ | ПРГ4 | робот по лінії (перша сходинка драбини): налаштування коефіцієнтів через Serial без перепрошивки; на ESP32 — в ЕМБ1.3–ЕМБ1.4; далі у біатлоністі і рятувальнику |
| labkit — модуль Python для CSV-вимірювань і графіків із похибками | ПРГ2 | лабораторні ЕЛ1.x і МЕХ1, залік з електрики, тижневі підсумки в інженерному журналі; у ML1.1 порівнюється з pandas |
| Ровер на сітці | ПРГ1 (і ПРГ3) | сітка зайнятості для BFS і A* в АЛГ3 — той самий формат карти |

Рішення про те, як саме консоль потрапляє на ESP32, ухвалює паспорт Embedded: програмування лише гарантує, що її код збирається без винятків і покритий тестами.

### ПРГ5 · Rust · за вибором

Rust — третя мова програми, тож її власник — той самий курс (принцип 1). Окремий курс заради одного модуля лише ускладнив би Карту.

- **Коли:** рік 3, поза лімітом двох модулів, як олімпіадний практикум; для 1–2 охочих, у сертифікат не входить.
- **Пререквізити:** ПРГ4 і ЕМБ1.2.
- **Зміст (≈13 год):** власність і позичання (ownership, borrowing); Option і Result замість nullptr і винятків; cargo і вбудовані тести; Rust на ESP32 через esp-hal (Embassy — зі зірочкою).
- **Бейдж:** консоль команд із ПРГ4, переписана на Rust і запущена на ESP32. На захисті учень показує, які свої помилки з ПРГ3–ПРГ4 компілятор Rust не пропустив би.
- **Чому рік 3:** головний аргумент Rust для робототехніки — безпека пам'яті на МК. Її відчуває лише той, хто вже ловив висячі вказівники в C++ і писав прошивку.
- **Ризик:** екосистема embedded Rust швидко змінюється, тож модуль переглядається щоліта. Матеріали пишемо не раніше за літо 2028: пілотний набір дійде до року 3 восени 2028.

У Карту ПРГ5 йде як модуль за вибором, поряд із LLM.
